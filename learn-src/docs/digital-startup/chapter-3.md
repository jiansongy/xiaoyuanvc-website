# 第三章　产品实务

## 一个想法，怎样接受真实检验？

发现问题、用 AI 做原型、让真实用户试用、根据反馈调整。课件在这里补了一层背景：工业革命让机器接手一部分体力劳动，AI 让机器开始接手一部分脑力劳动。创业者仍要用实际证据决定继续、调整或停止。

## 为什么要“疯狂而愚蠢”？

课件设计了一个“糟糕创意的反转庆祝”游戏。第一步是提出一个真实难题。第二步故意搜集最糟糕、最愚蠢、最灾难性的解决方案，让大家暂时放下对好点子的期待。第三步用笑声和庆祝营造安全的氛围。第四步才是关键：接过别人的一个“烂点子”，找出背后的核心逻辑，把它反转成一个可能有价值的商业方案。

## 创业是空白考卷

创业往往连考题都没有，需要自己找方向。课件把从想法到经营分为两个大阶段：先搜索和测试，再执行。搜索和测试又分成发现与验证。发现是测试基本假设，先判断方向对不对，用早期发现尽快纠偏。验证是拿到更强的证据，确认所选的方向有机会成为一门生意。

## 创业早期的 PMF

PMF（Product-Market Fit）是产品市场契合。课件把它比成电灯开关：当产品真正满足需求，客户开始追着你要买，愿意付钱。

写下自己的创业假设：**我们帮助谁，用什么办法解决什么问题？客户原本有哪些选择？他们为什么会选我们？**最后一个问题要讲出具体的差异。

## 需求分析 Y 模型

课件用“3.1 米高的卡车，怎么过 3 米高的山洞”提醒我们，用户说出的办法和他想完成的事，中间还有一步。先从表面需求找到用户目标，再往下问背后的人性需求，最后才回到产品功能。

课件借用乔布斯的比喻：婴儿会哭，却说不清自己需要什么。产品经理要用不同的办法去了解真正的需求。用心听，听完还要追问。

## 从用户的挣扎时刻开始

课件用“饥饿的人群比包子好吃更重要”来讲刚需。顾客觉得这件事非做不可，手头的替代办法又失效了，才更可能主动来找产品。

| 从功能出发 | 从挣扎时刻出发 |
| --- | --- |
| 我们做了一个笔记软件 | 期末复习，面对 1,000 页课件不知道从哪开始 |
| AI 写作助手 | 明天论文截止，今晚才发现思路是错的 |
| 二手交易平台 | 毕业要搬家，宿舍堆了一屋子没用的东西 |

## 问真事，看行动，再决定

“妈妈测试”提醒我们，越是关心你的人，越可能为了鼓励你而说喜欢。想听到可靠的信息，可以把访谈换个问法。

1. **问过去发生的事。** “上次碰到这个问题，你怎么解决的？”追问对方做过什么、花过多少钱，比问“这个产品你会买吗”更容易听到实情。
2. **让对方自己试一次。** 选一件他确实要做的事，观察他在哪一步卡住，需要多少帮助。你替他做完，就很难判断产品是否好用。
3. **根据结果作决定。** 对照原先的猜想和实际发生的事，再决定继续、修改还是停止。发现想法不成立，也省下了下一步投入。

## 妈妈测试的两个故事

同一个菜谱 App 的想法，可以有两种问法。故事 A 里，儿子告诉妈妈自己想做什么，请她评价。妈妈关心儿子，觉得点子很棒，还列出一堆理由。故事 B 里，儿子改问妈妈在厨房里实际遇到过哪些问题，才了解到能帮助产品决策的事情。
“如何问那些连你妈妈都无法欺骗你的问题？”《妈妈测试》用这个问题说明，容易让人说客气话的问题，也容易把创业者自己带偏。访谈时既要讲提问技巧，也要克制介绍自己方案的冲动。

## 最简方式先跑起来

智能体让开发更容易，也容易让人先做 App 再找客户。软件只是做生意的一种办法。能直接在微信上开始业务，就先用微信；到现有办法解决不了问题时，再开发。

## “聊天即记账”的创新

课件举的产品是“点记账”。用户关注服务号，像给朋友发微信一样说一句“午饭 28，奶茶 16”，后台就识别金额、分类、入账；想查时再打开小程序。传统工具要用户切换应用、学习操作，许多人很难坚持。这个产品借用了人们本来就会用的聊天框，减少了记一笔账的麻烦。

## 银罐艺术商店的店务问题

银罐艺术商店用掌银收款。它由手机应用和扫码器配合，顾客付费后，店员能在应用里看到收款。店员还会把卖出的货品拍照发到微信群，晚上再用照片核对收款记录。只核对钱，仍然不知道具体卖了什么货。于是课件提出，给银罐做一个能把货品和收款一起记清楚的数字员工。

## 用 Matt Pocock 的开发技能

Matt Pocock 是英国的技术教育者。他把经过工程实践检验的开发方法，写成智能体能按步骤执行的开源技能。这样可以把需求、原型、实现和检查留下记录，减少每次从头交代。课件给出的入口是 [AI Hero Skills](https://www.aihero.dev/skills)。

## 银罐项目用到的八个技能

| 技能 | 在银罐项目里做什么 |
| --- | --- |
| `setup-matt-pocock-skills` | 初始化开发环境，安装后先运行一次 |
| `grill-with-docs` | 把卖货、记账、退货、盘点的需求问清楚，记下来 |
| `to-spec` | 写清第一版的功能和验收标准 |
| `prototype` | 做出模拟微信聊天式记账的界面，让经营者试用 |
| `implement` | 开发数据库、记账界面和接口 |
| `tdd` | 先用测试检查库存是否重复扣减、金额是否算错 |
| `code-review` | 检查账目准确性、权限和数据安全 |
| `diagnosing-bugs` | 排查漏记、重复记账和接口异常 |

## 先跑通一笔账

课件建议先做通“拍照 → AI 识别 → 人工确认 → 保存销售记录”。这一轮稳定之后，再接库存、掌银对账和微信机器人。用这些技能的代价，是前期要多花时间确认和写文档；收获是过程更稳定、结果可以检查，质量较少依赖临场发挥。

## 银罐店务助手的演示界面

演示是一份模拟账本。收款照常用掌银；卖出东西后，店员可以拍照或选照片，也可以直接输入。课件里的演示输入是：“杯子和垫子各一个，一共 28 元，支付宝收款。”

识别结果先让人核对，确认后才入账并扣减已核实的库存。系统保留操作人，便于晚上核对。识别失败时，也可以手动记账。界面还能查看笔数、售出件数、退款金额和待确认草稿。课件原型的照片只在本地预览，演示数据可以刷新重置。
