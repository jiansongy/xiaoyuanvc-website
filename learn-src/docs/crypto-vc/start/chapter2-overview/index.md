# 第二章：实务、钱包与安全

加密资产把控制权交给用户，也把安全责任交给用户。本章不教你追逐收益，而是帮助你理解交易所、钱包、出入金与签名的边界，先学会保护自己。

::: danger 重要提醒
平台是否向你所在地区提供服务、可以使用哪些资金通道，取决于当地法律和平台规则。不要通过修改 IP、伪造身份或其他方式绕过地区限制。涉及真实资产前，应自行确认最新合规要求。
:::

## 为什么实务重要

公链是发动机，钱包和交易平台则像方向盘、钥匙和交通规则。链上产品通常公开可访问、迭代很快，但一个错误地址、一次恶意签名或一份泄露的助记词，也可能造成无法追回的损失。

本章贯穿三条底线：

1. **不懂就不签。**
2. **先小额验证，再扩大操作。**
3. **把长期资产、日常交互和高风险尝试隔离。**

## 交易所与钱包分别解决什么

中心化交易所（CEX）帮助用户完成法币入口、撮合交易和账户管理；自托管钱包连接公链和 DApp，让用户直接控制私钥。

| 维度 | 中心化交易所 CEX | 自托管钱包 |
| --- | --- | --- |
| 资产控制 | 平台托管或共同控制 | 用户自己控制私钥 |
| 登录方式 | 账号、密码、KYC、多因素认证 | 私钥或助记词派生账户 |
| 优点 | 上手简单、流动性高、找回机制较多 | 无需平台许可、可直接使用链上应用 |
| 主要风险 | 平台倒闭、冻结、黑客与账户风险 | 私钥丢失、钓鱼、恶意授权与误操作 |
| 更适合 | 了解市场和合规入口 | 小额链上学习与自主资产管理 |

[CoinGecko 交易所榜单](https://www.coingecko.com/en/exchanges) 可以帮助观察交易量、信任评分和市场格局。常见平台包括 Binance、OKX、Coinbase 和 Kraken，但排名不等于安全保证，也不代表平台在所有地区都可用。

### 一个产品视角案例：Binance

Binance 由赵长鹏在 2017 年创立，早期抓住了交易体验、资产覆盖和全球化服务的机会，快速成为大型加密交易平台。这个案例值得研究的不是“应该买什么”，而是三个创业问题：

- 新市场爆发时，产品速度与用户体验怎样形成优势？
- 全球扩张如何同时带来监管与组织挑战？
- CEX、钱包、公链和开发者生态怎样相互协同？

## 私钥、助记词与地址

| 概念 | 可以公开吗 | 作用 |
| --- | --- | --- |
| 地址 | 可以 | 类似收款账号，用来接收资产和查询记录 |
| 私钥 | 绝对不可以 | 生成签名，代表账户最高控制权 |
| 助记词 | 绝对不可以 | 按标准恢复一组私钥和地址 |
| 签名 | 需要逐项确认 | 授权转账、登录或智能合约操作 |

任何获得私钥或助记词的人，都可以控制对应资产。正规客服、平台和开发者不会向你索要这些信息。

## 钱包类型与使用边界

| 类型 | 例子 | 便利性 | 主要风险 | 建议用途 |
| --- | --- | --- | --- | --- |
| 托管热钱包 | 交易所账户 | 高 | 平台与账户风险 | 小额、短期使用 |
| 自托管热钱包 | MetaMask、Rabby | 较高 | 钓鱼、扩展、恶意授权 | 日常链上交互 |
| 硬件冷钱包 | Ledger、OneKey | 较低 | 设备、备份和供应链风险 | 长期、较大额保管 |

一种常见的分层方法是：长期资产放在很少交互的冷钱包，日常金额放在热钱包，新协议或空投使用独立的小额实验钱包。比例不是固定答案，关键是让一次事故不会影响全部资产。

## 钱包全生命周期安全

### 创建

- 只从官方渠道下载钱包，核对域名与发布者。
- 不把助记词输入网页、聊天窗口、云笔记或截图工具。
- 为不同用途创建相互隔离的钱包。

### 备份

- 备份的核心是助记词或私钥，而不是应用本身。
- 考虑火灾、丢失、设备损坏和继承等灾备场景。
- 定期在安全环境中验证备份是否真的可恢复。

### 使用

- 转账前逐字核对网络、币种和首尾地址，先发小额测试。
- 连接 DApp 前核对域名，不通过搜索广告进入高风险网站。
- 看清签名类型、授权对象和额度；不理解时拒绝签名。
- 定期通过 Etherscan Token Approvals、[Revoke.cash](https://revoke.cash/) 或钱包内置工具取消不必要授权。

## 两大核心安全法则

慢雾团队的开源《[区块链黑暗森林自救手册](https://github.com/slowmist/Blockchain-dark-forest-selfguard-handbook/blob/main/README_CN.md)》把安全习惯概括为：

- **零信任**：对平台、链接、陌生人、熟人转发甚至本教程保持合理怀疑。
- **持续验证**：通过官网、链上数据、签名内容和多个独立来源验证关键事实。

这不是悲观，而是把验证变成操作流程。

## 签名为什么是重灾区

一笔签名可能只是登录，也可能授权合约长期转走某种代币。钱包界面未必能把底层调用解释清楚，因此要坚持“所见即所签”：你看到的对象、金额、网络和权限，应当与预期结果一致。

签名前检查：

1. 当前是否为正确网络？
2. 对方合约地址是否来自项目官网？
3. 是一次性转账，还是无限额度授权？
4. 钱包模拟出的资产变化是否符合预期？
5. 这笔操作能否先用测试网或独立小额钱包完成？

## 设备和身份安全

- 保持操作系统、浏览器和钱包更新，不安装来源不明的程序与扩展。
- 为交易平台和邮箱启用独立强密码、密码管理器与硬件安全密钥或 2FA。
- 防范 SIM 卡转移攻击，重要账号不要只依赖短信验证码。
- 为重要电脑启用磁盘加密，并避免陌生 Wi-Fi。
- 将日常浏览、链上交互和长期资产管理尽可能隔离。

## 常见骗局

### 身份冒充

- 冒充项目方、导师、客服或熟人的账号主动私信。
- 在官方帖文评论区复制头像与名称，发布钓鱼链接。
- 伪造“账户异常”“必须立即验证”等紧迫情境。

### 高收益诱惑

- “稳赚”“保本”“内部带单”与只展示盈利截图的群组。
- 冒用知名交易所品牌的挖矿、理财和质押产品。
- 价格看似持续上涨、实际无法卖出的蜜罐代币。

### 社交私聊

陌生人先聊行情、持仓和共同兴趣，再引导到私域群、假平台或恶意合约。真正需要保护的不是某一句话，而是你的信息边界：不要透露持仓、钱包结构、验证码和设备信息。

## 如何看待市场指标

[ahr999](https://www.coinglass.com/zh/pro/i/ahr999) 等指标试图把历史价格和长期成本组合成观察框架。它们可以帮助理解市场情绪和历史周期，但不能预测未来，也不能替代风险承受能力、资产配置和独立研究。

使用任何指标时都问四个问题：数据来自哪里、公式是什么、在哪些时期失效、如果判断错误会损失多少。

## 安全检查清单

- [ ] 我知道资产由平台还是私钥控制
- [ ] 我有离线备份，并验证过恢复流程
- [ ] 我使用独立的小额钱包尝试新应用
- [ ] 我会核对域名、网络、地址、授权额度和资产变化
- [ ] 我不会绕过地区限制，也不会相信收益承诺
- [ ] 我能承受本次操作发生全部损失
