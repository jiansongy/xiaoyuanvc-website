# 第三章：以太坊与二层网络

如果说比特币重点解决“没有中央银行，怎样维护一套稀缺价值账本”，以太坊则继续追问：“没有中央服务器，能不能运行公开可验证的程序？”答案就是智能合约。

## 从数字货币到可编程产权

比特币像一台专注记账的计算器；以太坊更像一个公共操作系统。开发者可以把程序部署到共享账本，任何人都能调用，所有节点对执行结果达成一致。

以太坊有两类账户：

| 类型 | 由谁控制 | 能做什么 |
| --- | --- | --- |
| 外部账户 EOA | 私钥持有人 | 持有资产、签名并发起交易 |
| 合约账户 | 部署在链上的代码 | 按规则保存状态并执行逻辑 |

合约账户给代码提供了“住处”和“记忆”。每次交易触发合约时，网络读取旧状态、运行代码，再把新状态写回账本，于是形成可验证的可信计算。

## 比特币与以太坊的设计差异

| 维度 | 比特币 | 以太坊 |
| --- | --- | --- |
| 主要问题 | 如何安全记录和转移稀缺资产 | 如何运行可编程的公共状态机 |
| 核心状态 | UTXO 与 BTC 所有权 | 账户余额、合约代码和存储 |
| 程序能力 | 有意保持简洁 | 支持通用智能合约 |
| 常见应用 | 储值、支付 | 稳定币、DEX、借贷、NFT、DAO |
| 网络费用 | 交易手续费 | 按计算与存储消耗支付 Gas |

两者都依赖公开规则和分布式验证，但优化目标不同，不能只用“谁更快”来判断优劣。

## 六个基础概念

1. **账户**：记录余额、交易次数和状态的链上主体。
2. **地址**：公开标识，类似收款账号。
3. **私钥**：生成签名并控制外部账户的秘密凭证。
4. **签名**：证明某个操作获得私钥持有人授权。
5. **交易**：向网络提交的状态变更指令，如转账或调用合约。
6. **Gas**：衡量计算和存储消耗的单位，防止无限循环和资源滥用。

ETH 是以太坊网络的原生资产，用于支付 Gas。智能合约是程序，DApp 则是把用户界面、合约和其他服务组合起来的应用。

## 一笔交易怎样写进账本

| 阶段 | 发生的事 | 用户能观察什么 |
| --- | --- | --- |
| 创建 | 钱包组合接收方、金额、数据与费用参数 | 待签名内容 |
| 签名 | 私钥为交易生成数字签名 | 发送地址与交易哈希 |
| 广播 | 节点初步验证后放入内存池 | Pending 状态 |
| 执行 | 区块提议者选择交易并运行 EVM | Gas 使用量与执行结果 |
| 共识 | 其他验证者重新执行并确认区块 | 区块号和确认数 |
| 最终状态 | 余额、合约存储等状态被更新 | Success 或 Reverted |

即使合约执行失败，验证者也已经消耗计算资源，因此通常仍会收取 Gas。这也是为什么签名前要先理解调用内容、设置合理费用并用模拟工具检查结果。

## DApp 生态地图

[Ethereum Apps](https://ethereum.org/zh/apps/) 和 [DappRadar Heatmap](https://dappradar.com/heatmap) 可以帮助观察应用生态。常见类别包括：

- 支付与稳定币
- 去中心化交易和借贷
- NFT、游戏与社交
- 身份、治理和公共物品
- 开发者工具、预言机和基础设施

研究 DApp 时，不要只看用户数量，还要看合约是否开源、管理员权限、资金托管方式、收入来源和历史安全事件。

## CROPS：判断数字系统是否真正属于用户

本教程用 CROPS 概括以太坊社区长期重视的四个方向：

| 字母 | 原则 | 检查问题 |
| --- | --- | --- |
| CR | Censorship Resistance，抗审查 | 单一机构能否阻止合法用户使用？ |
| O | Open Source and Free，开源与自由 | 规则能否被检查、复制和改进？ |
| P | Privacy，隐私 | 系统是否只暴露完成服务所需的信息？ |
| S | Security，安全 | 网络和应用能否抵抗攻击与滥权？ |

CROPS 不是“已经全部实现”的产品清单，而是评估方向。部署在以太坊上的应用也可能保留管理员后门、冻结能力或中心化前端，因此“上链”不自动等于去中心化。

## 为什么需要二层网络

以太坊一层（L1）追求安全、数据可用性和最终结算，直接处理每一笔交易成本较高。二层网络（L2）在链外或独立执行环境中批量处理交易，再把必要的数据、证明或状态结果提交回一层。

| 层级 | 主要职责 | 类比 | 代表 |
| --- | --- | --- | --- |
| L2 | 快速执行、排序、批量压缩 | 食堂先处理大量校园卡消费 | Base、Arbitrum |
| L1 | 保存关键数据、最终结算与争议裁决 | 学校财务总账 | Ethereum |

### 一笔二层交易的流程

1. 用户在 Base 或 Arbitrum 上签名并发送交易。
2. 排序器快速排序、执行，用户很快看到结果。
3. L2 将许多交易压缩成一个批次。
4. 批次的数据、状态结果或证明被提交到 Ethereum。
5. Ethereum 保存必要信息，并承担最终结算与争议处理。

不同 L2 使用不同的证明、数据可用性和治理设计。低费用不意味着没有信任假设，研究时还要看排序器、跨链桥、升级密钥和提款机制。

## 用区块浏览器做一次只读研究

1. 打开 [Etherscan](https://etherscan.io/) 任意一笔公开交易。
2. 找到发送方、接收方、状态、区块、费用和 Input Data。
3. 如果交易调用合约，查看合约是否已验证源代码。
4. 观察 Token Transfers 与 Logs，理解一次操作可能触发多项状态变化。
5. 再在 [BaseScan](https://basescan.org/) 或 [Arbiscan](https://arbiscan.io/) 找一笔 L2 交易，对比费用与最终结算信息。

这项练习只读公开数据，不需要连接钱包。

## 本章小结

- 智能合约让区块链从价值账本升级为可编程公共平台。
- 交易经过签名、广播、执行、共识和状态更新，Gas 为计算资源付费。
- DApp 的去中心化程度取决于完整产品架构，而不只是合约部署在哪条链。
- L2 负责高效执行，L1 负责安全与最终结算；跨层设计带来新的信任和桥接风险。
